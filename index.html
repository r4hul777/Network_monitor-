1. Network Topology

Network Monitor replicates an enterprise filtered network environment divided across two distinct subnets connected via a central filtering router:

[Clients Subnet: 192.168.1.0/24] | (Workstations / Browsers) v +-------------------------------+ | Router & ACL Engine | <-- [Hot-Reload Policy] | (First-Match-Wins + Deny) | +-------------------------------+ v [Servers Subnet: 192.168.2.0/24] (Web 80/443, DNS 53, FTP 21)

All traffic traversing between the subnets is inspected packet-by-packet by the router ACL engine.

2. ACL Engine & Wildcards

The router enforces ordered Access Control Lists inspired by Cisco IOS architectures:

  • Ordered Evaluation: Rules are checked top-to-bottom. The first match wins and immediately decides the action.
  • Wildcard Masking: Uses bitwise inverse masks (e.g. 0.0.0.255 matches an entire /24 subnet).
  • Implicit Deny: Any packet not matching an explicit permit rule falls through to an automatic deny.
  • Hot-Reloading: Policies can be reloaded live without stopping the router or dropping sessions.

3. Foreign Packet Identification

How does the system identify and block unauthorized or foreign traffic?

  • Non-Permitted Protocols: If a policy specifies "Allow ONLY HTTP", any non-HTTP traffic (FTP, Telnet, SSH, ICMP, DNS) is identified and denied.
  • Unexpected Ports: Packets destined for unknown ports (e.g. port 9999 probes or backdoor attempts) are flagged and dropped.
  • Rogue External IPs: Any source IP outside 192.168.1.0/24 attempting access to internal servers is rejected by implicit deny.
  • Telemetry: Central Monitor tracks pass/drop ratios, bandwidth, and protocol anomalies in real time.
